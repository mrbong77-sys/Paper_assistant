# 지식 베이스 만들기

이 도구 세트에는 두 종류의 지식 베이스가 있습니다.

| 종류 | 위치 | 무엇 | 명령 |
|---|---|---|---|
| 문헌 지식 베이스(프로젝트별) | `projects/<slug>/02_literature/cards/` | 인용하는 논문마다 한 장의 카드: 서지 대조, 연구 요약, 원고에 쓸 수 있는 사실(쪽), 인용 문장별 판정 | `/pa-refs` |
| 작성 지식 베이스(공통) | `docs/style/core_rules.md`(공개), `knowledge/private/`(사용자의 책, 비공개) | 글쓰기 규칙을 ID와 함께. 검수와 윤문이 ID로 인용 | `/pa-kb` |

## 1. 문헌 카드 (S2)

1. **찾기.** 검색어·DB·날짜·결과 수를 `02_literature/search_log.md`에 남깁니다. alphaXiv·Semantic Scholar·Google Scholar·학회 기록 등 무엇을 쓰든 재현할 수 있게 적습니다.
2. **추가.** `python -m pa refs add --doi 10.xxxx/...` 또는 `--arxiv 2401.01234` 또는 `--title "정확한 제목"`. Crossref·arXiv의 원 기록에서 서지를 만들고 `verified`로 표시합니다.
3. **대조.** `python -m pa refs verify`가 손으로 넣은 항목을 포함해 모든 항목의 제목·연도·저자를 원 기록과 비교합니다. 게재본이 있는 프리프린트를 알려 줍니다. DOI도 arXiv 번호도 없는 자료(책, 보고서)는 사람이 확인하고 `python -m pa refs manual --key K --note "출판사 페이지에서 확인, ISBN ..."`.
4. **원문.** `PA_EMAIL=<연락용 주소> python -m pa refs fetch`는 Unpaywall이 알려 주는 열린 사본과 arXiv만 받습니다. 페이월을 우회하지 않습니다. 열린 사본이 없으면 "no open copy"로 적고, 사람이 도서관에서 받아 `papers/<키>.pdf`로 둡니다(HITL).
5. **텍스트.** `python -m pa refs text`(pdftotext 필요).
6. **인용 문맥.** `python -m pa refs contexts`가 원고에서 각 문헌을 인용한 문장을 찾습니다(`[@key]`, `\cite{key}`, "Author (2024)", "(Author et al., 2024)").
7. **카드.** `python -m pa refs cards`가 카드 뼈대를 만들고, Claude가 원문을 읽어 채웁니다.
   - 무엇을 한 연구인가: 질문, 자료, 방법, 주요 결과(수치와 쪽). 자기 말로 3–6문장. 긴 인용 금지.
   - 원고에 쓸 수 있는 사실: 한 줄에 사실 하나와 쪽 번호.
   - 인용 문장별 판정: Supported / Partly supported / Not supported / Wrong source / Usage citation. 근거는 짧은 인용과 쪽. 고칠 방향.
8. **관문 S2:** 모든 항목이 verified이고 카드에 자리 표시가 없고, 사람이 승인하면 열립니다.

원문 PDF와 추출 텍스트는 저작물이므로 커밋하지 않습니다(프로젝트 `.gitignore`). 카드는 요약과 짧은 인용만 담으므로 비공개 프로젝트 저장소에 커밋해도 됩니다.

## 2. 책 지식 베이스 (선택, 사용자가 가진 책)

공개 규칙 세트(`core_rules.md`)로 충분하지 않으면, 가지고 있는 글쓰기 책·학회 지침으로 자기만의 규칙 지식 베이스를 만듭니다. `/pa-kb <책 파일>`이 아래 절차를 따릅니다.

1. **저작권.** 책 원문과 그 상세 요약은 공개 저장소에 두지 않습니다. 결과는 `knowledge/private/`(git 제외)나 비공개 저장소에만 둡니다. 원문을 길게 옮기지 않고, 규칙은 자기 말로 한 줄씩 씁니다.
2. **층 정하기.** 책이 맡는 층을 정합니다: 이야기 구조, 섹션 관례, 문장·어휘, 참고문헌·윤리, 편집자 판정, 분야 관례. 같은 층에서 책끼리 부딪치면 어느 책을 따를지 정해 둡니다.
3. **ID 접두어.** 책마다 두세 글자 접두어를 정합니다(예: 저자 머리글자). 규칙은 `XX-01`부터 번호를 매기고, 한 번 매긴 번호는 바꾸지 않습니다.
4. **장별 추출.** 장마다: 규칙(한 줄, 명령문), 이유(한 줄), 점검 방법(검수자가 무엇을 보면 되는가), 원전 위치(장·절·쪽). 
5. **기계 점검 후보.** 표현으로 잡을 수 있는 규칙은 정규식 후보를 따로 모읍니다. 분야 프로필의 `extra_phrases`에 넣으면 `pa check`가 그 ID로 표시합니다.
6. **기존 규칙과 대조.** `core_rules.md`의 같은 규칙과 대응표를 만듭니다(같음 / 더 엄격 / 다름). 다르면 어느 쪽을 따를지 하우스 규칙에 적습니다.
7. **등록.** `knowledge/private/index.md`에 책 이름, 판, 접두어, 맡는 층, 파일 경로를 적습니다. `/pa-review`와 `/pa-polish`는 이 색인이 있으면 책 규칙 ID도 함께 인용합니다.

예시 파일 형식:

```
# KB: <책 제목>, <판> (<출판사>, <연도>)
- 접두어: AB   맡는 층: 문장·어휘   원전: 사용자 소장본, 원문은 저장소에 없음

| ID | 규칙 | 이유 | 점검 방법 | 원전 위치 |
|---|---|---|---|---|
| AB-01 | 주어를 문장 앞 열 단어 안에 둔다. | 독자는 주어를 찾을 때까지 문장을 붙들고 있다. | 주어 앞 단어 수를 센다. | 3장 2절 |
```
