# 원고 검수 절차 (8단계 + 편집자 판정)

- 적용: 초고를 다 쓴 뒤, 투고 전, 수정본 제출 전. 명령은 `/pa-review`(전체)와 `/pa-panel`(역할별 6인 검수)입니다.
- 실행 주체: **원고를 쓴 세션과 다른 세션**이 검수합니다. 같은 세션은 저자가 아는 맥락으로 빈틈을 메워 읽기 때문에, 처음 읽는 독자가 막히는 곳을 보지 못합니다(이른바 "지식의 저주"). 사람이 검수자일 때도 같습니다.
- 규칙 ID: [`docs/style/core_rules.md`](style/core_rules.md)(ST, SE, EV, DI, LA, KO, RE, ED, PK, RV)와 프로젝트의 하우스 규칙(HR, `01_topic/house_rules.md`).
- 검수자는 원고를 고치지 않습니다. 보고서만 씁니다. 고치는 일은 작성 세션이 보고서를 받아서 합니다.

## 0. 준비

1. **저널 규정표**가 채워져 있는지 봅니다(`01_topic/journal.md`): 분량, 초록, 키워드, 표·그림 상한, 참고문헌 형식, 맹검, 필수 선언문, 철자. 비어 있으면 그것이 첫 번째 차단 항목입니다.
2. **수치 근거**를 확보합니다: `05_data/numbers.csv`와 그 `source` 열의 결과 파일.
3. **저자의 의도**를 확보합니다: `01_topic/topic.md`의 확정 문장(O·C·RQ·A·R, 기여), `log/decisions.md`의 결정. 1단계의 대조에 씁니다.
4. **기계 점검**을 돌립니다. 결과는 5단계에서 엽니다. 1–4단계는 기계 결과를 보지 않고 먼저 진행합니다(기계 목록에 끌려 구조 문제를 놓치지 않게).
   ```
   python -m pa check 07_manuscript/manuscript.md --out 08_review/check_<날짜>.md
   python -m pa numbers audit
   python -m pa refs verify
   python -m pa fig check 06_figures/out
   ```

## 검수 단계

순서는 구조 → 명료성 → 흐름 → 언어입니다. 앞 단계에서 **차단**이 나오면 작성 세션이 고친 뒤 다음 단계로 갑니다. 구조가 바뀌면 문장 손질이 헛일이 되기 때문입니다.

### 단계 1. 이야기 검사 — 메시지가 서는가

- **입력:** 제목, 초록, 서론 첫 단락, 서론 마지막 단락, 고찰 첫 단락, 결론 마지막 단락. 본문은 아직 읽지 않습니다.
- **할 일:** 이 여섯 조각만 보고 O(큰 문제), C(공백·질문), A(접근), R(답), take-home message를 각각 한 문장으로 씁니다. 그 다섯 문장을 0단계의 저자 의도와 대조합니다.
- **차단:** 질문이나 답을 쓸 수 없음(ST-03, ST-01). 복원한 메시지가 저자 의도와 다름.
- **수정:** 문제 범위와 결론 범위가 다름(ST-05). 결과를 끝까지 숨김(ST-07). 새로움을 기법 자체에 둠(ST-06). 중요도나 쓰임이 없음(ST-11).

### 단계 2. 구조와 섹션 — 각 섹션이 제 일을 하는가

섹션마다 SE-01–SE-12를 확인합니다.

- **차단:** 방법만으로 재현할 수 없음(SE-07). 고찰에 결과에 없는 새 수치(SE-09). 자료가 지지하지 않는 결론(EV-08). 필수 선언문 누락(SE-12).
- **HR-03 점검:** 개발 이력, 버전 번호, "처음에는 ~했으나" 서술을 찾아 지우게 합니다. 연구 질문에 필요한 비교는 ablation으로만 씁니다.

### 단계 3. 근거와 수치 — 모든 주장이 뒷받침되는가

1. 원고의 모든 숫자를 수치 원장과 결과 파일에 대조합니다. 초록·본문·표·그림·보충 자료가 서로 같아야 합니다(EV-01). `numbers_audit.md`의 미추적 수치를 하나씩 판정합니다.
2. 반올림, 유효 숫자, 분모(EV-02), 불확실성 표기(EV-03).
3. "유의"는 검정과 함께만(EV-05).
4. 주장의 강도와 근거(EV-04), 사전 등록 조건 전부 보고(EV-06, `04_design/design.md`와 대조), 대안 해석(EV-07), 결론의 과잉(EV-08), 자료 격리(EV-09), 추정 서술(EV-10).
- **차단:** 근거를 찾을 수 없는 수치, 원고 안에서 서로 다른 수치, 검정 없는 "유의", 자료가 지지하지 않는 결론.

### 단계 4. 표와 그림

DI-01–DI-10을 확인합니다. `pa fig check` 결과를 이 단계에서 씁니다. 그림은 게재 크기로 렌더링해서 직접 봅니다.

### 단계 5. 문장과 어휘

기계 점검 보고서를 엽니다. 보고서는 **후보**만 표시하므로 항목마다 고칠지 남길지 판정합니다.

1. 1인칭(LA-16): 금지된 프로젝트에서는 0이어야 합니다.
2. 문장 길이(LA-01): 프로필의 검토선을 넘는 문장은 모두 보고, 상한을 넘는 문장은 나누게 합니다.
3. 어순과 정보 흐름(LA-02, LA-03, ST-09).
4. 간결성(LA-04–LA-08).
5. 모호성(LA-12), 용어(LA-10, LA-11, HR-07), 시제(LA-13), 문체(LA-23).
6. 한국어 원고는 KO-01–KO-14를 함께 봅니다.
7. 분야 문체는 [`docs/style/polishing.md`](style/polishing.md)의 분야별 점검표를 따릅니다.

### 단계 6. 참고문헌과 연구 윤리

RE-01–RE-10을 확인합니다. `pa refs verify`의 차이 목록과 문헌 카드(`02_literature/cards/`)의 판정을 씁니다. 카드에 Not supported 또는 Wrong source가 있으면 차단입니다.

### 단계 7. 최종 점검과 투고 묶음

PK-01–PK-10을 확인합니다. 기계 점검을 다시 돌려 자리 표시가 0인지 보고, `pa build package`로 빈 폴더에서 다시 조판되는지 봅니다.

### 단계 8. 편집자 판정 — 심사자라면 어떻게 읽는가

1–7단계를 마친 뒤, 원고를 처음 받은 편집자와 심사자의 눈으로 다시 읽습니다.

1. ED-01–ED-07에 한 줄씩 답합니다.
2. ED-08의 반려 사유를 하나씩 대입해, 심사자가 반려 근거로 쓸 수 있는 곳을 찾습니다.
3. 답이 "아니오"이거나 근거가 약하면, 원고의 어느 문장을 고치면 되는지 위치와 함께 적습니다.

- **차단:** 범위 불일치(ED-01), 자료가 결론을 지지하지 않음(ED-03), 준수 미충족(ED-05).

## 판정 등급과 보고 양식

- **차단:** 고치기 전에는 투고하지 않습니다. 메시지 실패, 재현 불가, 근거 없는 수치, 검정 없는 "유의", 금지된 1인칭, 남은 자리 표시, 확인 안 된 참고문헌, 저널 상한 초과, 필수 선언문 누락.
- **수정:** 이번 판에서 고칩니다. 섹션 규칙 위반, 긴 문장, 정의 없는 약어, 시제 오류.
- **권고:** 저자가 판단합니다. 문체 선택, 더 짧은 표현.

보고서는 `08_review/<YYYY-MM-DD>_review.md`에 둡니다. 템플릿: [`templates/review/review_report.md`](../templates/review/review_report.md).

```
# 검수 보고서 (YYYY-MM-DD)
- 대상: 07_manuscript/manuscript.md (커밋 abc1234)
- 검수자: <세션 이름 또는 사람>, 작성 세션과 다름

| 단계 | 판정 | 차단 | 수정 | 권고 |
|---|---|---|---|---|
| 1 이야기 | 통과 | 0 | 1 | 0 |
...
**차단 0건, 수정 6건, 권고 2건입니다.**

| # | 단계 | 등급 | 위치(섹션·줄) | 규칙 ID | 문제 | 고칠 방향 |
|---|---|---|---|---|---|---|
| 1 | 1 | 수정 | 서론 마지막 단락 | ST-03 | 질문 없이 목표만 있음 | "To learn X, Y was done" 꼴로 질문을 명시 |
```

- 보고서 첫머리의 **"차단 N건"** 줄은 관문 S8이 읽습니다. 형식을 지키십시오.
- 사람에게 보고할 때는 차단 항목과 결정이 필요한 항목만 올립니다(선택지와 권장안).
- 작성 세션이 고친 뒤에는 차단 항목과 기계 점검만 다시 확인합니다.

## 역할별 검수단 (선택, 큰 원고·최종본)

한 검수자가 모든 단계를 보면 뒤 단계가 얕아집니다. 원고가 크거나 최종본이면 역할을 나눠 동시에 돌립니다(`/pa-panel`, `.claude/agents/`).

| 역할 | 에이전트 | 맡는 단계 | 보고서 |
|---|---|---|---|
| 편집장 | `pa-editor` | 1, 2, 8 | `08_review/panel/<날짜>/editor.md` |
| 수치 감사 | `pa-numbers` | 3 | `numbers.md` |
| 표·그림 | `pa-displays` | 4 | `displays.md` |
| 언어 편집 | `pa-language` | 5 | `language.md` |
| 참고문헌·윤리 | `pa-references` | 6 | `references.md` |
| 투고 묶음 | `pa-package` | 7 | `package.md` |

각 역할은 읽기만 하고 자기 보고서 한 파일만 씁니다. 다 끝나면 작성 세션이 여섯 보고서를 하나의 `<날짜>_review.md`로 합쳐 차단·수정·권고를 셉니다.

## 수정본(심사 답변) 검수

심사 의견을 반영한 수정본에는 위 단계에 더해 RV-01–RV-08을 봅니다. `python -m pa round letter`가 기계적으로 확인할 수 있는 빈 답, 위치 없는 변경, 근거 없는 거절, 방어 문구를 먼저 표시합니다.
